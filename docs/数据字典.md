# 数据字典

数据库：SQLite，默认 `data/his_intel.db`。表结构定义见 [app/db.py](file:///d:/D_file/jgq_ys/newjob/tianyancha/app/db.py#L14-L165)。

## 1. 实体关系

```
regions(市州) 1──n hospitals(医院) 1──n announcements(公告) 1──n awards(中标结果)
                                                    └──n attachments(附件)
announcements ── hospital_id ──> hospitals.id
announcements 1──1 record_notes（按 ann_url 关联，稳定保留人工备注）
announcements 1──n notifications（新增命中站内提醒）
crawl_tasks 1──n crawl_logs
users / audit_logs / change_history / source_health 为运维与审计表
```

### attachments 附件

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| announcement_id | INTEGER | 关联公告 |

| kind | TEXT | `中标公告` / `招标文件` / `参数文件` / `其他` |
| source | TEXT | `announcement` 公告原文 / `direct` 页面可下载直链 / `manual` 人工上传 |

| sha256 | TEXT | 文件哈希（下载或上传后计算） |
| size | INTEGER | 字节数 |

- 唯一索引 `(announcement_id, url)`，同一公告同一链接不重复登记。
- 每个新公告自动登记一条 `kind=中标公告, source=announcement` 的原文附件。
- 直链解析最多 6 个、下载前 3 个；下载失败不重试即标记，不伪造文件。
- 手工上传限制扩展名（pdf/doc/docx/xls/xlsx/zip/rar/ofd/txt/jpg/png）与 `MAX_UPLOAD_MB`，写 `audit_logs`（`attachment_upload`）。
- `ATTACHMENT_CHECK_HOURS>0` 时后台线程定时复检 `source IN ('direct','manual')` 且无本地文件的附件。

### record_notes 中标记录备注

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 自增 |
| ann_url | TEXT UNIQUE | 关联 announcements.url，**稳定关联键**；不使用可能重建的自增 id |
| announcement_id | INTEGER | 冗余关联 announcements.id，便于按 id 查询 |
| note | TEXT | 文字备注，最长 2000 字 |
| tags | TEXT | 标签，逗号分隔、去重、最多 12 个（导入/页面均按中文逗号、顿号、分号、空格拆分） |
| status | TEXT | 处理状态；预置「跟进中 / 已联系 / 重点客户 / 已成交 / 待评估 / 无需跟进」，允许自定义，最长 40 字 |
| created_by / created_at | TEXT | 首次创建人与时间 |
| updated_by / updated_at | TEXT | 最近修改人与时间 |

- 备注、标签、状态全为空时删除该行，列表按「无备注」展示。
- 重新采集只更新 `announcements` 字段，不删除公告行；导入按 URL upsert，因此备注不会丢失。
- 每次增改/删除写 `change_history`（entity=`note`），接口调用另写 `audit_logs`（action=`note_update`）。
- 角色：admin/analyst 可写，viewer 只读。

### audit_logs 操作审计

`username`、`action`（login/collect/export/edit 等）、`detail`、`ip`、`ts`。

`source` UNIQUE、`last_check`、`status`（available/unreachable/error/blocked）、`http_code`、`note`。

## 3. 取数口径

### 每家医院最近 2 次

```sql
WITH filtered AS (
  SELECT a.id, a.hospital_id, COALESCE(a.publish_date,'') AS d
  FROM announcements a
  WHERE a.hospital_id IS NOT NULL AND a.is_void = 0
),
dated AS (
  SELECT hospital_id,
         CASE WHEN d = '' THEN 'id:' || id ELSE d END AS day_key,
         MAX(id) AS id, MAX(d) AS d, GROUP_CONCAT(id) AS ids
  FROM filtered GROUP BY hospital_id, day_key
),
ranked AS (
  SELECT id, hospital_id, d, ids,
         ROW_NUMBER() OVER (PARTITION BY hospital_id ORDER BY d DESC, id DESC) AS rn
  FROM dated
)
SELECT a.*, h.name AS hospital_name, r.rn, r.ids
FROM ranked r JOIN announcements a ON a.id = r.id
JOIN hospitals h ON h.id = a.hospital_id
WHERE r.rn <= 2;
```

- 排序：中标/发布日期倒序；同一天多包先按（医院, 日期）合并为 1 次，再取最近 2 个日期。
- 同一天多包：`ids` 汇总当日全部公告，中标单位/品牌去重合并，金额取当日最大包件金额，页面显示包件数。
- 流标/废标：`is_void=1` 直接排除，不占名额。
- 跨年：不按自然年截断，按最近 2 个日期取；年份筛选在分组前过滤，避免「先取 2 次再筛年份」漏数据。
- 无日期：以 `id:` 作为分组键，各自保留，不并入同一天。
- 品牌筛选：命中所选品牌即保留该公告。

### 组合筛选与导出

筛选在「每家医院最近 2 次」结果集上叠加，导出使用同一组参数：

| 参数 | 含义 |
| --- | --- |
| `city` | 市州行政区划代码 |
| `hospital_id` | 医院 id |
| `brand` | HIS 厂家品牌（含「未识别」） |
| `date_from` / `date_to` | 公告日期闭区间 `YYYY-MM-DD` |
| `amount_min` / `amount_max` | 金额区间，**入参单位为万元**，后端换算为元 |
| `q` | 关键词，匹配医院、项目、供应商、品牌、备注、标签、市州 |
| `has_note` | `1` 有备注/标签/状态，`0` 无 |
| `tag` | 标签精确匹配（按逗号拆分后的单个标签） |
| `status` | 处理状态精确匹配 |
| `year` | 年份（兼容旧参数，可选用日期区间替代） |

无有效金额的记录在设置金额区间时会被排除；清空筛选即不传任何参数。

### HIS 相关度

`his_relevance(title, full_text)`：标题命中关键词 +3，正文命中 +1，`score >= 3` 入库。关键词表见 `config/his_keywords.txt`。

### 金额解析

`extract_amount` 支持 `123.45万元`、`1,234,567.89元`、中文大写（壹佰贰拾万元整）等，统一换算为元。无金额返回 `(None, "")`。

### 品牌置信度

| 置信度 | 依据 | 页面标识 |
| --- | --- | --- |
| 0.9 | 规则库/供应商名称命中 | 正常显示品牌 |
| 0.85 | 供应商名称命中品牌别名 | 正常显示品牌 |
| 0.55–0.6 | 集成商（电信/联通/移动/铁塔/数智/系统集成）+ 正文或包件佐证 | 「待核」 |
| 1.0 | 人工确认 | 正常显示品牌，`review_status='confirmed'` |
| 0 | 无命中 / 集成商无佐证 | 「未识别」，进入待核队列 |

禁止将未命中记录强行归入某品牌；代理机构（招标/咨询/采购中心）置 `is_winner=0`，不计入未识别占比。
